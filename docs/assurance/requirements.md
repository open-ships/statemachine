The shared `scripts/check.sh`, `scripts/fuzz.sh`, and `scripts/benchmark.sh` drive local and CI verification. Repository verification runs `go test`, `go test -race`, `go vet`, errcheck, staticcheck, formatting, a coverage floor, root-module vulnerability scanning, separate SQLite integration race tests, per-change fuzz smoke runs of every target, benchmarks, and a scheduled sustained fuzz campaign. Failing fuzz inputs are retained under `testdata/fuzz` as permanent regression seeds. After successful CI on the current `main` commit, the commit-pinned shared release workflow reruns source verification, creates an annotated tag automatically, and retains the source artifact, coverage, toolchain, SBOM, checksums, and separate build-provenance and SBOM attestations.

The [first stable validation record](first-stable-validation.md) records the local checks and limits of the 1.4.0 preparation.

| INT-AUTH-001 | One externally enforced writer/lease per actuator, with durable monotonic fencing and controller rejection of stale commands. |
